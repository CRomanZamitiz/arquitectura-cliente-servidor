1. El Problema del Texto Plano en Cliente-Servidor

Antecedentes (Min 00-10)
  • Las llamadas al sistema de sockets (send(), recv(), write(), read()) transmiten arreglos de bytes directamente desde la RAM hacia la pila TCP/IP sin protección nativa.
  • Vulnerabilidad crítica frente al modelo UIT-T X.800:
    • Intercepción (Confidencialidad): Captura de tráfico mediante Sniffers en modo promiscuo.
    • Modificación (Integridad): Alteración de bytes en tránsito por un atacante Man-in-the-Middle.
  • Objetivo de la sesión: Transformar el buffer en memoria local (textoOriginal → textoEncriptado) y resguardar la llave antes de acoplarlo a un par de programas Cliente-Servidor.

2. Criptografía Simétrica: Estándar AES-256 (FIPS 197)

Teoría Criptográfica (Min 10-25)
  • Emplea la misma llave criptográfica (K) tanto para cifrar como para descifrar.
  • Tamaño de bloque fijo: AES opera sobre bloques exactos de 128 bits (16 bytes).
  • Longitud de llave en AES-256: Requiere 256 bits (32 bytes) y ejecuta 14 rondas de transformación matemática.
  • En C, un unsigned char mide exactamente 1 byte (8 bits) sin signo, ideal para almacenar bytes binarios puros.

3. Modo CBC, Vector de Inicialización (IV) y Padding

Teoría Criptográfica (Min 10-25)
  • Modo CBC (Cipher Block Chaining): Aplica una operación lógica XOR (⊕) entre cada bloque de texto plano y el bloque cifrado anterior para eliminar patrones repetitivos.
  • Vector de Inicialización (iv[16]): Bloque aleatorio de 16 bytes que se opera con XOR contra el primer bloque de texto plano.
  • Relleno (Padding PKCS#7): Completa el último bloque si el mensaje no es múltiplo de 16 bytes. Por ello sumamos EVP_MAX_BLOCK_LENGTH al tamaño del arreglo textoEncriptado.

4. Bibliotecas OpenSSL en C y la Interfaz EVP

Arquitectura OpenSSL (Min 25-35)
  • OpenSSL en sistemas Linux se compone de dos bibliotecas dinámicas: libssl (protocolos TLS/DTLS) y libcrypto (algoritmos criptográficos puros, CSPRNG y certificados).
  • Cabeceras utilizadas en cripto.c:
    • <openssl/evp.h>: Interfaz de alto nivel EVP (Envelope) para cifrado y descifrado.
    • <openssl/rand.h>: Generador de números pseudoaleatorios criptográficamente seguro.
  • Ventaja de usar EVP: Sustituye a las APIs obsoletas de bajo nivel y activa automáticamente las instrucciones de aceleración por hardware del procesador (AES-NI).
// Librerías de OpenSSL necesarias para la criptografía en cripto.c
#include <openssl/evp.h>
#include <openssl/rand.h>

5. Entropía CSPRNG y Descarga de Llave a Archivo (llave.key)

Persistencia Binaria (Min 35-45)
  • RAND_bytes() extrae entropía del kernel del sistema operativo para poblar llave[32] e iv[16] con bytes impredecibles.
  • Descarga a disco (llave.key): Se abre en modo escritura binaria ("wb") porque los 32 bytes crudos pueden contener el byte 0x00 (nulo) o 0x0A (salto de línea). El modo texto corrompería la llave.
// Generar bytes aleatorios seguros para la llave (32B) y el IV (16B)
if (!RAND_bytes(llave, sizeof(llave)) || !RAND_bytes(iv, sizeof(iv))) {
    manejarErrores();
}
// Guardar la llave generada en un archivo binario "llave.key"
FILE *archivoLlave = fopen("llave.key", "wb");
fwrite(llave, 1, sizeof(llave), archivoLlave);
fclose(archivoLlave);

6. Máquina de Estados EVP: Proceso de Encriptación

Análisis de Código (Min 35-45)
  • 1. Creación del contexto (EVP_CIPHER_CTX_new): Reserva una estructura opaca ctx en el Heap.
  • 2. Inicialización (EVP_EncryptInit_ex): Carga el motor EVP_aes_256_cbc(), la llave y el iv.
  • 3. Cifrado de bloques (EVP_EncryptUpdate): Cifra el mensaje y guarda los bytes escritos en longitudPaso.
  • 4. Cierre y Padding (EVP_EncryptFinal_ex): Usa aritmética de punteros (textoEncriptado + longitudPaso) para concatenar el bloque final de relleno.
EVP_CIPHER_CTX *ctx = EVP_CIPHER_CTX_new();
EVP_EncryptInit_ex(ctx, EVP_aes_256_cbc(), NULL, llave, iv);
EVP_EncryptUpdate(ctx, textoEncriptado, &longitudPaso, textoOriginal, longitudTextoOriginal);
longitudTextoEncriptado = longitudPaso;
EVP_EncryptFinal_ex(ctx, textoEncriptado + longitudPaso, &longitudPaso);
longitudTextoEncriptado += longitudPaso;

7. Máquina de Estados EVP: Desencriptación y Limpieza

Análisis de Código (Min 35-45)
  • Reinicio del contexto (EVP_DecryptInit_ex): Configura la operación inversa con la misma llave y el mismo iv.
  • Validación de integridad en EVP_DecryptFinal_ex: Verifica y retira el padding. Si el texto cifrado o la llave fueron alterados, devuelve distinto de 1 y ejecuta manejarErrores().
  • Terminador nulo y liberación: Se agrega '\0' al final para imprimir con %s y se libera el Heap con EVP_CIPHER_CTX_free(ctx).
EVP_DecryptInit_ex(ctx, EVP_aes_256_cbc(), NULL, llave, iv);
EVP_DecryptUpdate(ctx, textoDesencriptado, &longitudPaso, textoEncriptado, longitudTextoEncriptado);
longitudTextoDesencriptado = longitudPaso;
EVP_DecryptFinal_ex(ctx, textoDesencriptado + longitudPaso, &longitudPaso);
longitudTextoDesencriptado += longitudPaso;
textoDesencriptado[longitudTextoDesencriptado] = '\0';
EVP_CIPHER_CTX_free(ctx);

8. Práctica Guiada: Compilación y Verificación Forense

Laboratorio Linux (Min 45-60)
  • Paso 1: Compilar cripto.c indicando al enlazador (linker) que vincule la biblioteca libcrypto mediante la bandera -lcrypto.
  • Paso 2: Ejecutar el binario pasando como argumento entre comillas la cadena a cifrar.
  • Paso 3: Comprobar que el archivo llave.key tiene exactamente 32 bytes (256 bits) e inspeccionar sus bytes hexadecimales.
# 1. Compilación enlazando libcrypto de OpenSSL
$ gcc -Wall cripto.c -o cripto -lcrypto

# 2. Ejecución del programa
$ ./cripto "Mensaje confidencial para la arquitectura Cliente-Servidor"

# 3. Inspección forense de la llave generada en disco
$ ls -l llave.key
$ hexdump -C llave.key
